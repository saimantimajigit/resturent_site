### Prepare fresh QR access for each presentation

The old seeded T03 seating interval is historical and must never be lengthened. It is retained for audit/history and may be expired. After starting the selected server, open a second PowerShell terminal and run the host workflow fixture preparation against that exact origin:

```powershell
# Development
$env:SAVORE_DEMO_BASE_URL='http://localhost:3015'
npm.cmd run demo:qr:prepare
npm.cmd run demo:smoke

# Production preview, after the production server is running
$env:SAVORE_DEMO_BASE_URL='http://localhost:3016'
npm.cmd run demo:qr:prepare
npm.cmd run demo:smoke
```

Preparation signs in as the fictional customer and host, creates a policy-valid reservation for the next service day through the customer API, confirms table/waiter assignment and check-in/seating through host APIs, then rotates the selected table QR identity and activates its session through staff QR management. The raw QR token is written only to ignored `.env.client-demo`; the script never prints it or a URL containing it. Read it only through the operator's approved local secure process to present it in a browser. Repeating preparation while the fixture remains current reuses that seating rather than creating duplicate active sessions. After a completed QA run, a new invocation creates a fresh run-scoped reservation. Expired seating is never extended. Preparation uses only customer and host logins; the application’s authentication limit remains active. Do not clear `AuthRateLimit` after repeated smoke runs—wait for the configured 15-minute window if a sign-in is throttled.

`npm.cmd run demo:journey` runs the full connected API/database scenario and ends with guest departure, closed QR session, and released occupancy. Use it for QA; it changes demo records and consumes that run's active QR fixture. Run `demo:qr:prepare` again before a client presentation. These commands use only the existing marked demo database, never reset it, and do not touch the other two databases.

Do not expose either local server to the LAN. Do not start a second Next process using the same output directory. Do not stop a process unless it is confirmed to belong to this checkout.
